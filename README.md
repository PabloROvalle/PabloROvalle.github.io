# Personal academic website — Planetary Atmospheres (V2)

One-page personal website, written in HTML + CSS + JavaScript. No build tools or paid hosting needed.

## Preview locally
Open `index.html` in your browser. The photograph is included locally at `assets/mountain-night-sky.png`.

## Publish free with GitHub Pages (without terminal)

1. Sign in to GitHub and click **+ → New repository**.
2. Name it **YOURUSERNAME.github.io** (replace YOURUSERNAME with your GitHub account username). Make it **Public**.
3. Create the repository. On the repository page choose **uploading an existing file** or **Add file → Upload files**.
4. Upload the **contents of this folder**, not the ZIP itself: `index.html`, `styles.css`, `script.js`, `assets/` (including the image). Keep the folder structure.
5. Select **Commit changes**.
6. Go to **Settings → Pages → Build and deployment**. Choose **Deploy from a branch**, branch **main**, folder **/(root)**, then **Save**.
7. After deployment completes, open `https://YOURUSERNAME.github.io/`. The Pages screen displays the published URL.

If your repo is instead called `my-website`, the address is typically `https://YOURUSERNAME.github.io/my-website/`.

## Make it yours (important before sharing)
- Replace all instances of `Your Name`, `YN`, placeholder years, jobs, and papers in `index.html`.
- Replace the example research text with your real research areas, methods and projects.
- Add accurate DOI links to the publications and your real links to ORCID, Google Scholar and email.
- The present generic publication links and email link are deliberately not active.
- The CV download link is also omitted until you add an actual `assets/cv.pdf`.
- Check that you have permission to publish the photograph and any other photos you add.
- Be aware: public GitHub repository contents are visible to everyone. Do not upload private data.

## Editing later
Edit any file in GitHub and commit the changes; GitHub Pages will redeploy automatically.

## Technical notes
All image URLs are relative, so this site works at the root or in a subfolder. Animations respect reduced-motion preferences; mobile backgrounds avoid fixed attachment.
